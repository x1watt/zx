Every archive is a database.

Backups that remember every version. Files found in microseconds by SHA-256 or by similarity. Compression with the models of cmix and paq8px when you have the time. And it still opens every 7z, zip, rar and tar you have. Pure Dart: a library, a command line and a file explorer for desktop and Android.

Five ideas no other archiver combines

zx reads and writes the formats you already use, then goes further.

zcm

Ultra-compression, cmix class

The models of cmix and paq8px in a normal archiver: smaller than paq8px on English text and source code, within 0.05 to 3.5% on images, audio and binaries. -m0=zcm:auto -mtime=10m picks the strongest level your machine can do in the time you give it.

backup

Backups that remember (zpaq style)

Every update appends a dated version and never rewrites old data. Identical chunks are stored once across files and versions; restore the archive as it was on any day, or list one file's timeline. Real zpaq archives too.

zxdb

Every archive is a database

SQL in SQLite's dialect, key-value stores, time series, full-text search and time travel, inside the archive and 5 to 20 times smaller than SQLite. Descriptions, tags, subtitles and screenshots travel with the files.

search

Find files instantly

SHA-256 lookup in 2 microseconds; the 20 files most similar to any file, among a million, in under 15 ms (TLSH). Duplicates and near-duplicates in one query.

NOSTR

Signed with NOSTR keys

An admin and maintainers, named by their npubs, sign each version. Anyone can check who signed what and that nothing changed afterwards, even without the password of an encrypted archive. How it works

The .zx format

The extension only says "zx can read this". Every block names the codecs that made it, so new algorithms never need a new extension.

Explicit compatibility

Each file records the oldest zx that can decode it. An older zx refuses at once: "needs zx 0.7.0 or later".

Versions with dates

Updates append; old bytes are never rewritten. Read the archive as of any date, list one file's timeline, compact when you want the space back.

Deduplication

Content-defined chunks are stored once across files and versions: a second version of a source tree costs 0.3 MB instead of 4.8 MB.

Parallel and safe

Blocks coded by worker isolates, 3x faster on 4 threads with identical output, within a memory budget. A crash mid-update is simply ignored.

Find by content

SHA-256 per file in a sorted table, and a TLSH digest to find similar files.

Volumes over disks

Volume sizes per disk, destination folders with budgets, search folders when reading; old disks can stay offline.

Archives that describe themselves

A README.md inside is shown when the archive or one of its folders is opened, like a git repository. Its images come from the archive itself: links out are allowed, fetching is not (zx readme -check).

zxdb: a database inside every archive

SQLite's SQL, checked against sqlite3 with fuzzing, plus key-value stores, time series and search, all stored with zx's compression. Every commit is a version, so every table can be read as it was.

Signed versions, with NOSTR keys

Anyone who holds a file can change it. A sealed .zx archive makes every change visible. Its admin and maintainers are NOSTR identities: each version is signed with one of their keys, and the npubs that may sign are written in the archive for every reader to see.

$ zx a -msign=@admin.nsec book.zx chapters/     # sealed, this key is the admin
$ zx seal -sign=@admin.nsec -add=npub1l702... book.zx
$ zx u -msign=@maint.nsec book.zx chapters/     # a maintainer's update
$ zx seal -full book.zx

Npubs you can see

The admin, every maintainer and the signer of every version are listed as npubs by zx seal, by zx l -slt and in the app. They are stored in the clear, so even an encrypted archive tells you who maintains it.

Changes show

Each version's seal covers a SHA-256 of every byte it stored and of its index, chained to the version before, and is signed (BIP-340). A changed byte, a forged version, a stripped seal or a key that may not sign is reported.

Roles that change

The admin adds and removes maintainers, decides whether they may sign, and can hand the admin role to a new key, which accepts it with its own signature. Versions signed by a removed maintainer stay valid; its later ones do not.

Optional, any time

Switch sealing on for a new archive or one with years of history, and off again. An archive that is never sealed is written and read exactly as before. Updates without a key stay "not signed" until an allowed key signs a later version.

Databases too

Every database commit is a version: it can be signed at each commit or every few seconds, and the last commits are signed when the database is closed. A compaction is sealed again by the admin.

What it can not prove

A seal tells you which npub signed; recognizing that npub is up to you, as on NOSTR. And an older, validly sealed copy can not tell that newer versions exist: publish your latest version where your readers follow you.

Keys are given as an nsec, as @file, or in the ZX_NSEC variable, so they never appear on the command line. The format is in the .zx specification, section 17.

The app: a file explorer that walks into archives

Desktop and Android. Browse your drives, and step into archives, nested archives, disk images and firmware as if they were folders.

Explorer

Places, drives and bookmarks, breadcrumbs that continue into archives, list and icon views, search, trash, conflict handling.

Archives as folders

Copy out to extract, paste in to add. Compress to .zx, Extract here and Extract to folder in every context menu.

Versions and data

.zx archives show their versions and a Data view: tables, key-value stores, time series, queries, metadata and "find similar".

Seals at a glance

A sealed archive shows Sealed, Not signed or Seal broken in the status bar; one click lists the npub that signed each version, the admin and the maintainers, and runs the full check.

Integrated

File associations and "Extract to folder" in the file manager on Linux; storage access, SD and USB volumes, open-with and share on Android.
